# Electron 界面验收

`electron-acceptance.test.mjs` 使用 Playwright 启动真实 Mesnier Electron 应用。业务操作通过实际按钮、输入框和弹窗执行；`getSnapshot()` 只用于核对宿主记录，不代替界面触发业务动作。

运行前按仓库实际构建命令生成 `dist/` 与 `build/runtime/`，然后在仓库根目录运行：

```bash
node --test tests/ui/electron-acceptance.test.mjs
```

当前启动路径针对 macOS Electron，未证明其他平台支持。完整模式启动仓库内的可控 HTTP 模型服务，再由真实宿主、受管 Node 进程与 Kimi harness 执行工具。它验证协议和产品行为，不代表真实模型的推理质量或第三方模型兼容性。

## 可选环境变量

| 变量 | 用途 |
| --- | --- |
| `MESNIER_APP_ROOT` | 指向要验收的已构建应用工程；默认当前仓库。测试只读取该工程。 |
| `MESNIER_ELECTRON_PATH` | 指定 Electron 可执行文件；默认工程 `node_modules/electron` 的 macOS 路径。 |
| `MESNIER_UI_EVIDENCE` | 本次独立证据目录；默认 `.evidence/ui/<时间戳>`。每次使用新目录，避免混入旧状态。 |
| `MESNIER_UI_MODE=smoke` | 只检查无需内核执行的界面与持久化；不证明可发送状态下的 IME、工具、权限和取消。 |
| `MESNIER_UI_FIXTURE_MODULE` | 指定可控模型服务模块；默认 `tests/acceptance/fixtures/model-server.mjs`。 |

测试先把当前构建复制到证据目录的 `app-snapshot/` 并核对关键文件哈希，随后始终运行该副本，避免并行构建或重启中途更换验证对象。支持时使用文件系统写时复制节省空间。

测试始终覆盖应用的 `MESNIER_HOME` 为本次证据目录下的 `data/`，不会使用用户的 `~/.mesnier`。工作文件分别放入本任务创建的系统临时非 Git 目录和显式初始化的 Coding 仓库；通过实际 `git rev-parse` 判断目录类型，不能凭目录名或未执行 `git init` 就认定为非 Git。初始化测试仓库不读取用户全局 Git 配置，不修改用户 Git 设置。

## 验证范围

- 空态无演示数据；深浅主题与最小窗口；模型新增、编辑、默认切换、删除回退和凭据不进入快照。
- 普通目录项目、会话和任务创建；输入草稿隔离；筛选、任务编辑、会话重命名；重启历史。
- 可发送状态下中文组合输入不误发送；活动执行期间输入保留为后续草稿。
- Chat → Board → Chat 保持原执行和权限请求；同次批准重复点击不重复放行；拒绝工具不写文件。
- 非 Git Work 与 Git Coding 的真实文件变化；看板启动、Agent 指派、产物预览、缺失文件错误和用户明确验收。
- 执行中修改默认模型不改写当前快照；取消保留已经发生的文件操作；显式重试产生新记录并使用新配置。
- 服务错误传播与凭据脱敏；活动执行退出后重启不重放，用户显式提交后恢复同一原生会话。
- 供应方没有提供用量时显示“未提供”；显式真实零保留零；正数统计正确包含输入缓存，后续缺失不沿用旧执行的值。
- 产物复制通过受控宿主接口写入系统剪贴板；复制前仅在测试内存中临时保存原文本，核对已知测试文本后恢复，原内容不进入日志或证据。如果原剪贴板含非文本格式，为完整保留用户内容而跳过复制，并在报告中明确标注。

截图禁用过渡动画并按 CSS 像素保存。除页面整体宽度外，测试还核对输入区与详情面板的几何位置，防止“页面没有滚动溢出”掩盖发送按钮被遮挡的问题。

## 证据与未覆盖项

每次生成 `report.json` 与截图。报告包含实际应用仓库 SHA、未提交文件清单、入口和渲染资源哈希、运行时完整目录摘要及 Node 哈希、测试源文件哈希、目录类型检查、逐项结果及执行关联。`runtime-tree.json` 记录所有运行时文件、动态分块和符号链接，不能只用入口 `worker.mjs` 的哈希代表整份分发。未提交构建结果不能直接宣称为干净提交的验证结果。

失败保留截图和原因；资源收尾失败会同时把报告判为失败并使测试进程非零退出。只关闭本任务创建的 Electron 进程与本地模型服务；强杀验收仅向本次 Electron 进程发送 `SIGKILL`，核对自身运行时是否退出，发现孤立进程则清理并判为失败。保留本次隔离数据和临时工作目录供复核，后续清理只应针对报告列出的这些路径。

自动化通过路径输入创建项目，没有覆盖原生目录选择器操作、Finder 窗口或发行签名、公证流程；这些检查不能从本测试通过推导。真实模型、安装包和其他平台须分别保留实际证据。运行时、主进程或界面后续变化影响本测试覆盖路径时，应针对新构建重新执行。

## 已安装应用与真实本地模型

`packaged-real-model.test.mjs` 直接启动指定的已安装 `.app`，通过真实本地模型服务执行读取笔记、审批写入、产物预览、看板验收和重启恢复。未提供下列三个必填变量时，测试明确跳过；不会以可控响应替代真实模型。

```bash
MESNIER_INSTALLED_APP=/Applications/Mesnier.app \
MESNIER_REAL_MODEL_URL=http://127.0.0.1:65050/v1 \
MESNIER_REAL_MODEL=mesnier-local-qwen3-4b \
node --test tests/ui/packaged-real-model.test.mjs
```

模型服务须由调用者先启动。端口和模型名称是本轮示例，按实际服务设置；需要鉴权时可额外提供 `MESNIER_REAL_API_KEY`。测试不会停止或重新配置该服务。模型推理最长等待十分钟，整轮超时十五分钟。`MESNIER_UI_EVIDENCE` 同样用于指定本次独立证据目录。

应用子进程的 `PATH` 仅设为 `/usr/bin:/bin:/usr/sbin:/sbin`，并逐一检查该搜索路径中不存在 `kimi`、`kimi-code`、`codex`、`claude` 和 `opencode`。这证明本次运行不从搜索路径使用已有独立 Agent CLI，不代表机器上没有安装过这些程序。测试核对 `isPackaged`、真实应用可执行路径、Resources 路径及代码签名，并在前后计算完整 Resources 目录摘要，绑定实际运行的安装文件。

所有业务变化仍通过界面操作，实际状态只读核对；仅批准与指定输出文件精确匹配的 `Write` 请求，范围外请求会拒绝并判为失败。本次配置和普通工作目录保持隔离，重启后核对执行数、事件数、产物哈希及修改时间，确认没有自动重放。不会操作剪贴板。完整报告与截图保留在证据目录；已安装应用的原生文件夹选择器、Finder 展示、公证和其他平台仍需独立验证。
