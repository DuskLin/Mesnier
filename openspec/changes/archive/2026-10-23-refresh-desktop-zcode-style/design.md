## Context

现状和目标见 proposal.md。参考本地 ZCode `3c5b227649371507ddc4eb46ac5133afe6db1cab`：`packages/ui/src/styles.css` 的字号变量，`app-shell/WorkspaceShellLayout.tsx` 的 264px 侧栏与 480px 对话宽度保护，`prompt-editor/ChatPromptEditor.tsx` 的 16px 圆角输入框，`app-shell/workspaceShellWindowChrome.ts` 的面板留白。只借鉴设计原则，以 Mesnier 原有组件实现。

## Goals / Non-Goals

统一真实工作台各入口的视觉层级。配色来自现有 Logo：蓝色主操作、青绿成功状态，中性背景支持深浅主题。既有执行、持久化、权限及主题偏好保持原样；不增加字号设置、可拖拽分栏或移动端产品入口。

## Decisions

- 长期规则以根目录 DESIGN.md 为准；AGENTS.md、贡献指南和 PR 模板建立读取与验收约束。
- 字号集中到 CSS 变量：基准14、说明13、辅助12、微标签10、次标题16、标题18、设置页专用标题24/30、欢迎标题18；业务内容不使用9～10px。替代遍布组件的独立字号，便于统一维护。
- 普通桌面侧栏264px，窄桌面收紧至220px；主面板独立浅边框、轻圆角；输入框16px圆角。保留 Mac 红绿灯安全区。
- 不复制 ZCode 的自动关闭状态逻辑：Mesnier 详情承载授权操作，改为可用主工作区不足约800px时将详情放到独立覆盖层，仍能显式关闭；覆盖时遮罩阻止误点被遮住的输入区。宽度允许时恢复并排，不修改选中任务与草稿。
- 使用容器查询按主内容可用空间换行工具栏、压缩边距；低于480px时隐藏次要快捷键提示，表单双列在窄窗口变单列；看板保持列内可读与横向滚动。
- 不采用大面积品牌渐变；保留原有蓝青 Logo，正文、表单、状态优先保证对比度。

## Risks / Trade-offs

- 字号增大可能导致窄窗口溢出 → 在1000×700最小窗口及打开详情、长任务/路径时实测几何位置与截图。
- 详情覆盖可能遮挡主内容 → 独立遮罩、明确关闭入口；测试关闭后草稿与选择仍保留。
- CSS改变不证明内核运行正确 → 运行既有界面套件，真实模型、发行安装单独标记未验证。

无数据迁移。恢复本次 renderer 文件即可回退样式。测试使用独立数据和构建副本，不覆盖正在使用的已安装应用。
