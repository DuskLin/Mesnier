## Why

原有规划把 Mesnier 定位为第三方 Agent CLI 的管理与适配工作台，首版需要处理安装、接口差异和多个运行时的兼容性。现已决定以新版 Kimi Code 源码作为可二开的执行底座，让 Mesnier 直接掌握默认运行时，并集中建设参考 ZCode 的工作交互和参考 Multica 的看板体验。

## What Changes

- 将默认执行路线改为应用内置和管理的 Kimi Code 派生运行时，首版不要求用户预装第三方 Agent CLI。
- 明确三方角色：Kimi Code 提供执行内核基础；ZCode 提供功能与交互参考；Multica 提供看板、卡片与任务组织参考。
- 在产品层与派生内核之间建立集成边界，记录上游基线、派生版本、模型配置和执行事件，逐步验证权限、取消与恢复能力。
- 以同一份项目、会话、任务、执行和产物记录支撑 Chat 与 Board，保留 Work 不依赖 Git、运行成功不等于任务验收完成等约束。
- 调整首个可用版本的路线：先验证底座与工程方案，再完成内置运行时、模型配置、对话关联看板、基础文件交付和验收闭环。
- 同步 README、OpenSpec 项目上下文与贡献指南中的项目状态和检查适用性。

### 范围与阶段

本次交付仅为规划调整：提案、增量规格、设计和后续实施任务，不引入上游代码、不运行 Agent、不改变真实账号或参考仓库。下述能力均是拟实施的首个工作闭环；任务完成并通过真实验证之前，不归档为已交付规格。

本变更的拟实施范围是本地受管运行时和基础 Chat / Board 闭环。远程主机、Web 入口、多 Agent 自动协作、定时任务、第三方 CLI 适配，以及完整的文档／表格／演示文稿／浏览器工具集仍属后续路线图，不纳入本次能力验收。

## Capabilities

### New Capabilities

- `managed-agent-runtime`：应用管理基于 Kimi Code 的派生运行时，提供独立配置、模型连接、执行事件与控制、版本记录及恢复边界。
- `unified-workbench`：以统一工作记录连接对话和看板，支持任务关联、Agent 指派、执行历史、基础产物和用户验收。

### Modified Capabilities

无。当前 `openspec/specs/` 为空，没有已交付能力可修改；原 README 中的多 CLI 路线是未实施规划，不存在已发布接口的破坏性变更。

## Impact

- **当前文档**：README、`openspec/config.yaml` 与贡献指南；本目录保存拟新增行为、设计、后续任务和本次文档验证记录。
- **未来代码**：工作台、任务与执行管理、派生内核集成、运行时分发和本地持久化。当前均无实现，桌面框架、宿主、通信和存储方案需在工程初始化前确定。
- **依赖与来源**：拟基于 `MoonshotAI/kimi-code` 源码二开并保留许可与上游记录。ZCode、Multica 当前只作设计参考，不自动复制其服务、账号体系或依赖。
- **数据与兼容性**：未来使用 Mesnier 自有数据目录，启动和升级需验证内核及会话版本；不默认读取既有 Kimi、ZCode 或 Multica 配置。
- **验证**：本次只执行文档与 OpenSpec 检查。运行时构建、真实模型、权限、取消、重启恢复及平台验收留在实施任务中，不能由静态检查替代。
