# managed-agent-runtime Specification

## Purpose

定义 Mesnier 内置 Agent 运行时的用户可见契约，使用户无需预装第三方 Agent CLI 即可配置模型并执行任务，同时明确独立数据、执行记录、权限交互、取消和重启恢复的行为边界。

## Requirements

### Requirement: 应用管理默认运行时

系统 SHALL 准备并管理应用自己的默认 Agent 运行时，在已验证的平台上不依赖用户预先安装第三方 Agent CLI，并明确显示运行时可用状态。

#### Scenario: 未安装外部 CLI 的环境开始工作

- **WHEN** 用户在满足已声明系统依赖、但未安装第三方 Agent CLI 的环境中首次启动应用并完成模型配置
- **THEN** 系统能够使用受管运行时发起执行，不要求用户先安装独立的 Agent CLI

#### Scenario: 运行时或系统依赖不可用

- **WHEN** 受管运行时准备失败或缺少必要系统依赖
- **THEN** 系统说明原因和处理方式，阻止执行进入运行中状态，并且不静默改用用户机器上的其他 Agent 安装

### Requirement: 独立配置与模型就绪状态

系统 SHALL 在 `~/.mesnier`（测试显式指定独立根）保存运行配置、会话、任务、日志、缓存和凭据引用，不默认读取、迁移或修改其他 Agent 应用的数据。系统 SHALL 区分运行时可用与模型服务可用，在提交前检查模型配置是否存在、必要字段是否有效，并阻止使用已被显式连接检查判定异常的配置。连接检查由用户主动触发，验证服务响应与基础工具调用。尚未测试的配置可以发起实际请求，但不得显示为连接已验证；实际请求返回的认证、能力或服务错误 SHALL 关联到执行记录并呈现。凭据值不得进入普通执行日志或配置快照。

#### Scenario: 用户已安装其他 Agent 应用

- **WHEN** 用户机器已有 Kimi、ZCode 或其他 Agent 的配置和会话
- **THEN** Mesnier 首次初始化使用独立数据范围，不自动继承其登录、修改其配置或迁移其会话

#### Scenario: 未配置或显式测试失败

- **WHEN** 模型配置不存在，或主动连接检查已经返回认证、服务或工具调用错误
- **THEN** 系统说明原因并阻止使用该配置开始任务，直到用户修改配置或重新检查通过，不把内核就绪当作模型验证通过

#### Scenario: 使用尚未测试的配置

- **WHEN** 用户选择有效但尚未进行连接检查的配置提交任务
- **THEN** 系统保留未测试标识并发送实际请求，将返回的认证、能力或服务错误关联到这次执行；不声称已做过连接验证

### Requirement: 执行身份与版本可追溯

系统 SHALL 为每次执行分配唯一记录，保存内核的上游基线与派生版本、Agent 和模型配置快照、工作目录、会话关联及状态。重试 SHALL 创建新执行记录；执行期间修改默认 Agent 或模型配置 SHALL 仅影响后续执行。

#### Scenario: 正在执行时修改默认配置

- **WHEN** 用户在某次执行进行中修改默认 Agent 或模型配置
- **THEN** 当前执行保持原配置记录，后续执行使用新配置，历史记录不被覆盖

#### Scenario: 对失败任务发起重试

- **WHEN** 用户显式重试一次失败或取消的执行
- **THEN** 系统创建可关联到原执行的新记录，保留原错误、事件和产物，并说明是否沿用原会话与工作目录

### Requirement: 结构化事件与权限响应

系统 SHALL 向工作台提供可关联到执行的回复、工具调用、工具结果、权限请求、用量可用性和错误事件。需要用户授权的工具操作 SHALL 在收到有效授权前保持等待；拒绝请求不得执行该次被拒绝操作，迟到或重复响应不得再次触发操作。

系统的首版桌面手动策略 SHALL 对文件写入、文件编辑与 Bash 命令逐次申请批准；Git 与非 Git 工作目录使用相同确认规则，读取沿用内核默认规则。单次批准不得变为后续写操作的隐式授权。

#### Scenario: Git 项目中的文件写入

- **WHEN** 用户在 Git 工作树内启动或恢复会话，Agent 请求 Write/Edit/Bash 操作
- **THEN** 系统在执行该操作前显示对应的权限请求；拒绝后不得产生该次操作的副作用，不因 Git 可恢复性自动放行

#### Scenario: 拒绝工具权限请求

- **WHEN** 执行提出工具权限请求，用户选择拒绝
- **THEN** 该次工具操作不执行，系统记录拒绝结果，并呈现内核随后继续、阻塞或结束的实际状态

#### Scenario: 工具或模型调用失败

- **WHEN** 工具执行或模型请求返回错误
- **THEN** 工作台显示关联的失败信息和当前执行状态，不用界面完成提示替代真实结果，不将缺失的用量记录显示为零消耗

### Requirement: 可核对的执行控制

系统 SHALL 提供显式取消入口，并以运行时确认和事件核对取消结果。执行中追加指令等控制操作 SHALL 按已接入能力提供；不支持时必须说明限制。系统不得因视图切换、控制请求超时或恢复页面而重新执行可能产生副作用的操作。

#### Scenario: 取消正在执行的任务

- **WHEN** 用户取消正在执行的任务
- **THEN** 系统先展示正在停止，在确认执行停止后记录取消；保留已经产生的事件和文件，不宣称取消撤销了既有副作用

#### Scenario: 取消未能确认

- **WHEN** 取消请求超时或与运行时的连接中断
- **THEN** 系统显示状态待核对和原因，不直接标记已取消、已完成或自动启动重复执行

#### Scenario: 当前不能追加指令

- **WHEN** 用户在执行中尝试追加指令，而该控制能力尚未接入或当前状态不允许
- **THEN** 系统明确提示限制，保留用户输入供后续提交，不静默丢弃输入或重新启动任务

### Requirement: 重启后的历史与状态核对

系统 SHALL 在应用重启后恢复可读取的执行历史，将未确认结束的旧活动执行标记为中断；首版不提供活动进程热重连。用户明确提交新输入或重试时才使用可兼容的原生会话创建新执行。版本不兼容时 SHALL 保留原数据并给出恢复限制，不自动重放可能已有副作用的操作。

#### Scenario: 重启后明确继续原会话

- **WHEN** 应用重启后用户查看保留的历史，并明确向可兼容的原会话提交新输入
- **THEN** 系统保留旧执行的真实终态或中断状态，以原生会话上下文创建新的执行，不重发旧输入或伪装原活动进程仍在继续

#### Scenario: 重启时执行丢失或会话不兼容

- **WHEN** 原执行已不存在、状态无法确认，或保存的会话与当前内核版本不兼容
- **THEN** 系统保留已有记录并显示中断、待核对或不兼容原因，在用户明确选择恢复或重试之前不重新执行任务

### Requirement: 可安装且独立运行的 macOS 应用

系统 SHALL 交付命名为 Mesnier 的 macOS 应用和安装包，携带界面资源、Node 运行时及锁定内核；双击启动后无需开发服务器或用户预装 Kimi CLI。系统 SHALL 提供使用说明、上游来源和与版本绑定的验证证据。

#### Scenario: 安装后双击启动

- **WHEN** 用户在当前已验证 macOS 电脑安装 Mesnier 并双击启动
- **THEN** 应用显示真实工作台，能够配置模型与工作目录并使用内置运行时执行任务

#### Scenario: 区分模拟和真实验证

- **WHEN** 发布记录包含可控模型服务与真实模型验收
- **THEN** 两类结果分别列明，缺失的真实模型、实际界面或安装启动实测不得记作完成
